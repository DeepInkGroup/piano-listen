# Piano Listen

A private, browser-based piano transcription studio. Microphone audio stays on your device. Recognize multiple notes and common chords, view a grand-staff score, correct notes, and export your music.

## Run locally

```sh
npm ci
npm run dev
```

Visit the URL Vite prints. Microphones require HTTPS or localhost. A phone opening a computer's LAN HTTP address cannot use the microphone; use the HTTPS GitHub Pages deployment instead.

## Use

1. Open the app in Safari on iPhone. Tap **Share → Add to Home Screen** to install it.
2. Tap **Start listening**, allow the microphone, then play one piano in a quiet room. Keep the screen awake and the app in front. Recording stops and saves when the app goes into the background, the microphone disconnects, or two minutes elapse.
3. Stop, listen back, set the tempo you played at, and optionally re-analyze the recording. Use the sliders button below the score to correct notes and timing.
4. Export **MIDI**, **MusicXML**, or **Print / Save as PDF**. On iPhone, use the share sheet to save exports to Files. The original take is also available as WAV until a new recording or page reload.

The app also imports audio files (up to 30 MB and two minutes). **My pieces** retains up to 30 scores in this browser's local storage. Export important pieces: browser storage can be cleared or evicted. Audio is held only in memory and is never uploaded or saved in local storage.

## Detection and notation limits

The detector uses a Hann-windowed 16,384-sample FFT and sparse nonnegative harmonic fitting across MIDI 21–108 (all 88 piano keys). Analysis runs in a worker; capture uses an AudioWorklet. It estimates up to 10 simultaneous pitches and uses temporal stabilization for note boundaries. The visible keyboard shows C2–B6; the engine also analyzes pitches outside that view.

This is approximate acoustic transcription, not perfect recognition of every chord. Real pianos differ from the harmonic template. Dense voicings, very low bass, background sound, tuning, fast repeated notes and sustain pedal can produce missed/extra notes or merged durations. Re-analysis uses the same detector with overlapping windows and the current sensitivity; it is not a separate AI model or a guarantee of improved accuracy. No claims about acoustic accuracy on real instruments have been established. Tests use synthesized signals.

Chord labels match common triads, suspended, sixth, seventh, ninth, eleventh and thirteenth chords and inversions; unknown pitch sets are displayed as notes. Chord names are interpretive and may be ambiguous. The score uses a C major / A minor key signature, 4/4, and sixteenth-note quantization at your chosen tempo. The split between hands is middle C. Set the tempo before exporting. MIDI preserves detected timing; MusicXML uses quantized timing, rests, and ties. PDF uses the browser's print dialog.

## Offline / PWA

The production service worker caches the app shell, local assets, and analysis worker. After the first complete online visit it runs offline. No CDN is needed for detection or notation; Google Fonts are an optional online enhancement with system-font fallbacks. Icons are generated by `scripts/prepare-assets.mjs`. Relative URLs support deployment below a GitHub Pages repository path.

## GitHub Pages

From an authenticated terminal with network access, run `./scripts/publish.ps1`. It checks the build, creates a public `piano-listen` repository in your GitHub account, enables Pages, and pushes the source. To choose a different name, use `./scripts/publish.ps1 -RepositoryName your-name`.

The included workflow builds and publishes on pushes to `main`. Create a public repository and select **Settings → Pages → Source → GitHub Actions**, then push:

```sh
gh repo create piano-listen --public --source=. --remote=origin --push
gh api --method POST repos/OWNER/piano-listen/pages -f build_type=workflow
```

If Pages already exists, use PATCH instead of POST. The deployed address is `https://OWNER.github.io/piano-listen/`.

## Checks

```sh
npm test
npm run build
npm run test:browser
```

Browser checks use Playwright Chromium (install with `npx playwright install chromium` if needed) and the Vite preview server. Unit tests cover synthetic polyphonic detection, chords, tracking, score quantization and exports. Browser checks cover the responsive interface, exports, editor, storage, microphone permission failure, synthesized microphone recording, import, PWA asset loading and offline behavior. These do not replace a physical iPhone or acoustic-piano test.
